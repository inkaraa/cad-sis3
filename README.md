# SIS 3 — Orders system as code (Cloud Application Development, KBTU)

An orders API on **ECS Fargate behind an ALB** publishes an `OrderPlaced` domain event to **SNS**.
SNS delivers it to an **SQS** queue (with a **DLQ**, `maxReceiveCount: 5`). An **idempotent Lambda**
consumer records each order in **DynamoDB** using `orderId` as the deduplication key.
Everything is defined in **CloudFormation** — nothing is created in the console.

## Repository layout

| Path | What it is |
|---|---|
| `app/` | Orders API (Node.js 24, non-root container, `/health`, `POST /orders`) |
| `consumer/` | Idempotent SQS consumer (Python 3.13 Lambda) |
| `infra/base.yaml` | Stack 1: ECR repository + S3 bucket for Lambda code |
| `infra/app.yaml` | Stack 2: VPC, ALB, ECS service, 2 IAM roles, SNS, SQS + DLQ, Lambda, DynamoDB, alarm |
| `deploy.sh` | **The one deploy command** |
| `destroy.sh` | Deletes everything for one environment |

## Prerequisites (manual, one-time)

- An AWS account with MFA on the root user; AWS CLI v2 signed in (`aws login` or `aws configure`)
- Docker running; git; optionally `cfn-lint` (`pip3 install cfn-lint`)
- Region: `eu-north-1` (override with `AWS_REGION=...`)

## Deploy — one command

```bash
./deploy.sh dev          # or any environment name, e.g. ./deploy.sh defence
```

Creates two stacks, `sis3-<env>-base` and `sis3-<env>-app`. Resource names are generated by
CloudFormation, so several environments can run side by side in one account.
The image tag is the git commit that last changed `app/` — never `latest`.

## Try it

```bash
URL=$(aws cloudformation describe-stacks --stack-name sis3-dev-app \
  --query "Stacks[0].Outputs[?OutputKey=='AlbUrl'].OutputValue" --output text)
curl "$URL/health"
curl -X POST "$URL/orders" -d '{"orderId":"o-1","total":100}'
```

- Same `orderId` twice → second one logged as `DUPLICATE skipped`, table unchanged
- `{"orderId":"poison-1"}` → fails 5 times (~25 min) → lands in the DLQ → alarm goes to `ALARM`

## Tear down

```bash
./destroy.sh dev
```

## Known limitations (deliberate, for a course environment)

- HTTP only (no domain for an HTTPS certificate)
- No NAT gateway: tasks run in public subnets with public IPs; the task security group accepts
  port 8080 only from the ALB security group
- Single account: environments are separated by stack name and the `Env` parameter
